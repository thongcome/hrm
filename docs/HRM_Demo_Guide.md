# คู่มือเตรียมและดำเนินการ Demo — HumanOk (HRM)
> ฉบับ 2026-08-31 · **เอกสารภายในทีม ห้ามส่งให้ลูกค้า** (มีรหัสผ่านบัญชีทดสอบ)
> คู่กับเอกสารฟีเจอร์ `docs/HRM_Feature_List.md` (เวอร์ชัน 1.0 ฉบับเผยแพร่ทางการ) — ทุกรายการในนั้นติ๊ก ✅ ทดสอบครบแล้ว demo ได้ทุกโมดูล

## 1. เตรียมเครื่องก่อน demo

1. เปิดระบบ: จากโฟลเดอร์ `D:\GitWorkspace\HRM` รัน

   ```bash
   dotnet run --launch-profile http
   ```

   แล้วเปิดเบราว์เซอร์ที่ **http://localhost:5052**
2. รหัสผ่านบัญชี demo ทุกบัญชีถูกตั้งกลับเป็นค่าที่รู้แน่นอน **ทุกครั้งที่ระบบเริ่มทำงาน** (อัตโนมัติ เฉพาะโหมดพัฒนา) — ถ้าใครเผลอเปลี่ยนรหัสระหว่างซ้อม แค่ restart ระบบก็กลับมาใช้รหัสตามตารางได้เหมือนเดิม
3. ซ้อมไล่ตามบท (ข้อ 3) อย่างน้อยหนึ่งรอบก่อน demo จริง — โดยเฉพาะฉากที่ต้องสลับบัญชี

## 2. บัญชีผู้ใช้สำหรับ demo

ช่องชื่อผู้ใช้ในหน้า login ใช้ **loginname** (ไม่ใช่อีเมล)

| บทบาทใน demo | ชื่อผู้ใช้ | รหัสผ่าน | เป็นพนักงาน |
|---|---|---|---|
| ผู้ดูแลระบบ / ฝ่ายบุคคล (เห็นทุกเมนู) | `admin` | `Dev@12345` | สมหญิง รักงาน (003) |
| ฝ่ายบุคคลเงินเดือน + **ผู้อนุมัติของ workflow ส่วนใหญ่** | `test_payroll` | `Test@12345` | สมชาย ใจดี (002) |
| หัวหน้างาน (มีสิทธิ์ admin ด้วย) | `005` | `Dev@12345` | ปราณี สุขใจ (005) |
| หัวหน้างาน (มีสิทธิ์ admin ด้วย) | `012` | `Dev@12345` | ชาญวิทย์ บุญมี (012) |
| พนักงานทั่วไป (ESS ล้วน) | `008` | `Dev@12345` | ธีระพล แสงทอง (008) |
| พนักงานทั่วไป (ESS ล้วน) | `009` | `Dev@12345` | นภัสสร วงศ์ษา (009) |
| พนักงานทั่วไป (ESS ล้วน) | `010` | `Dev@12345` | ประยุทธ ชัยมงคล (010) |

จุดสำคัญที่ต้องจำ:

- **`test_payroll` คือคนกดอนุมัติ** — ทุกเรื่องที่ยื่นเข้า workflow (ลา, OT, IDP ฯลฯ ตามค่าตั้งต้นของฐานทดสอบ) จะไปโผล่ในกล่องอนุมัติ (`/wf/my-inbox`) ของบัญชีนี้ ฉากอนุมัติทุกฉากให้สลับมาบัญชีนี้
- บัญชีพนักงานทั่วไป (008/009/010) จงใจ **ไม่มีสิทธิ์ admin เลย** — ใช้โชว์ว่าพนักงานเห็นเฉพาะของตัวเองจริงๆ (เข้าหน้า admin จะถูกปฏิเสธ)
- แนะนำเปิด 2 เบราว์เซอร์ (หรือ 1 ปกติ + 1 incognito) ค้างไว้: ฝั่งซ้าย login พนักงาน ฝั่งขวา login test_payroll/admin — สลับฉากได้โดยไม่ต้อง logout ไปมา

## 3. บทเดินเรื่อง demo แนะนำ (เรียงตามความน่าสนใจต่อผู้ชมฝ่ายบุคคล)

### ฉากที่ 1 — พนักงานยื่นลาด้วยตัวเอง (ESS)
- login `008` → เมนู ESS → **คำขอลางาน** (`/leave-requests`)
- ชี้ให้ดู: การ์ดไอคอนประเภทลา (กดสลับเป็นแบบรายการได้), สิทธิคงเหลือโชว์ทันทีที่เลือกประเภท, ชื่อพนักงานถูกล็อกเป็นตัวเอง
- ยื่นลาป่วย 1 วัน → กด **ส่งขออนุมัติ** → สถานะ PENDING
- แวะโชว์ **ปฏิทินทีม** (`/leave-requests/team-calendar`): สลับ "ตามหน่วยงาน / ทั้งบริษัท", ป้ายแดง "วันสุดท้าย" ของคนที่กำลังพ้นสภาพ

### ฉากที่ 2 — หัวหน้าอนุมัติ แล้วเรื่องวิ่งเอง
- สลับไป `test_payroll` → **กล่องรออนุมัติ** (`/wf/my-inbox`) → เห็นคำขอของ 008 → อนุมัติ
- กลับฝั่ง `008` refresh → สถานะเป็น COMPLETED
- ประโยคขาย: "ทุกเรื่องอนุมัติในระบบนี้ ลา OT เบิก จ้างงาน ประเมินผล วิ่งผ่านเอนจิ้นเดียวกันหมด ตั้งค่าสายอนุมัติได้เองไม่ต้องเขียนโปรแกรม"

### ฉากที่ 3 — ฝ่ายบุคคลทำลาแทน + ยกเลิกคำขอ
- ยัง login `test_payroll` (หรือ `admin`) → เมนู **ลา (แทนพนักงาน)** (`/leave-requests/on-behalf`) — เลือกพนักงานคนไหนก็ได้ ยื่นแทนได้
- โชว์ปุ่ม **ยกเลิกคำขอ** กับคำขอที่ยัง PENDING → เรื่องหายจากกล่องอนุมัติทันที ไม่ค้าง

### ฉากที่ 4 — เงินเดือน: แดชบอร์ด → AI ตรวจ → อนุมัติงวด
- login `test_payroll` → โมดูลเงินเดือน (`/pay/runs` และแดชบอร์ด)
- เดินเรื่อง: ภาพรวมปี → เจาะงวด → เจาะรายคน → เห็นรายการย่อยรายบรรทัด
- ชี้ AI ตรวจความผิดปกติก่อนจ่าย และ Maker-Checker (คนคำนวณอนุมัติเองไม่ได้)
- ปิดท้าย: สลิปอิเล็กทรอนิกส์ + เอกสารภาษี (50 ทวิ / ภ.ง.ด.1) ที่กดออกจากระบบได้เลย

### ฉากที่ 5 — การตั้งค่าที่ไม่ต้องแก้โปรแกรม (จุดขาย config-first)
- login `admin` → **ตั้งค่าประเภทการลา** (`/leave-requests/leave-types`): เพิ่มประเภทลาใหม่สดๆ ให้ดู 1 ประเภท แล้วกลับไปหน้า ESS ให้เห็นว่าการ์ดโผล่ทันที
- แวะ **สิทธิการลา** (`/leave-requests/policy`) ให้เห็นว่ากำหนดจำนวนวัน/ทบวันลา/อายุงานขั้นต่ำต่อบริษัทได้เอง
- ประโยคขาย: "กฎหมายเปลี่ยน นโยบายเปลี่ยน HR แก้เองได้ทั้งหมด ไม่ต้องรอผู้พัฒนา"

### ฉากที่ 6 — รับคนเข้า: สมัครงานสาธารณะ → สัมภาษณ์ → จ้าง
- เปิดหน้ารับสมัครสาธารณะ (ไม่ต้อง login) ให้เห็นฟอร์ม + ขอความยินยอม PDPA
- login `admin` → เดินตาม pipeline ผู้สมัคร → แบบให้คะแนนสัมภาษณ์ตามสมรรถนะของตำแหน่ง → การเสนอจ้างผ่านอนุมัติ
- ชี้: จ้างเสร็จระบบสร้างประวัติพนักงาน + เริ่ม checklist ปฐมนิเทศอัตโนมัติ + มอบหมายคอร์สบังคับให้เอง

### ฉากที่ 7 — คอร์สบังคับและ LMS
- login `admin` → **คลังหลักสูตร** (`/lms/courses`) → เปิดหลักสูตรตัวอย่าง ชี้ส่วน "บังคับสำหรับ (Mandatory Training)" — ตั้งได้ว่าบังคับพนักงานใหม่ทุกคนหรือเฉพาะตำแหน่ง
- **ติดตามคอร์สบังคับ** (`/lms/mandatory-compliance`): เห็นรายชื่อใครยังไม่เรียน
- สลับ `008` → **ประวัติการอบรมของฉัน** (`/ess/lms/my-training`): กล่อง "คอร์สที่ต้องเรียน (บังคับ)" + ปุ่มลงทะเบียน + ทำแบบทดสอบ (ไม่ผ่านเกณฑ์ = ยังไม่จบหลักสูตร)

### ฉากที่ 8 — ประเมินผลและ OKR
- login `admin` → โมดูลประเมินผล: โครงตัวชี้วัด 2 ชั้นถ่วงน้ำหนัก, การประเมินหลายทิศทาง, หน้า Calibration แบบเทียบข้ามทีม
- **เป้าหมาย OKR** (`/perf/goals`): เลือกรอบ → โชว์ tree บริษัท→หน่วยงาน→บุคคล → บันทึก check-in ที่เป้าลูก แล้วชี้ว่าความคืบหน้าเป้าแม่ขยับเองอัตโนมัติ

### ฉากที่ 9 — รักษาคนเก่ง (ปิดท้ายให้จำ)
- login `admin` → **Talent Pool** (`/talent/pool`): ตาราง "ความเสี่ยงการลาออก" พร้อมเหตุผลรายคน (ย้ำ: เกณฑ์ปรับได้ที่ `/talent/settings` และปิดเป็นค่าเริ่มต้น องค์กรเลือกเปิดเอง)
- **Succession** (`/succession/bench-strength`): heat-map ตำแหน่งเสี่ยง + ตำแหน่งที่ไม่มีคนสำรอง
- ประโยคปิด: "ระบบไม่ได้แค่จ่ายเงินเดือนถูก แต่ช่วยให้เห็นล่วงหน้าว่าจะเสียใครไป และมีแผนรับมือ"

### ฉากเสริม (ถ้ามีเวลา/ผู้ชมสาย IT)
- ความปลอดภัย: log การเข้าถึงข้อมูล (PDPA), ป้าย "ข้อมูลอ่อนไหว" บนหน้าจอ, เพิกถอน session (`/admin/system/user-sessions`), สิทธิ์ระดับเมนู/ปุ่ม
- SSO: HumanOk เป็นศูนย์กลาง login (OIDC) ให้ระบบอื่นในเครือ

## 4. ข้อควรระวังระหว่าง demo

- **ระบบจำกัดการ login ไว้ 5 ครั้งต่อนาที** (มาตรการกันเดารหัสผ่าน — เป็นจุดขายด้านความปลอดภัย แต่จะกัดเราเองถ้าสลับบัญชีรัวๆ ตอน demo) — นี่คือเหตุผลจริงจังของคำแนะนำ "เปิด 2 เบราว์เซอร์ค้าง login ไว้" ในข้อ 2: login ทุกบัญชีที่ต้องใช้ให้เสร็จ **ก่อนเริ่ม** demo แล้วสลับหน้าต่างเอา อย่า logout/login กลางเรื่อง ถ้าเผลอโดนจำกัด ให้ชวนผู้ชมคุยไป ~1 นาทีแล้วค่อยลองใหม่
- ทุกโมดูลในเอกสารฟีเจอร์ผ่านการทดสอบแล้ว เปิดโชว์ได้ทั้งหมด (31 ส.ค. 2569: 9-Box, Career Path, Engagement Survey, KM, เบิกค่าใช้จ่าย, คลังสมรรถนะ ปิดการทดสอบครบเป็นชุดสุดท้าย) — แต่ยึดบทเดินเรื่องหลักไว้ก่อน โมดูลเสริมเปิดเมื่อถูกถามจะราบรื่นกว่าพยายามโชว์ทุกอย่างในรอบเดียว
- ฐานข้อมูลนี้เป็นข้อมูลทดสอบ — วันที่ในระบบเป็นปี 2569 และมีรายการทดสอบเก่าปนอยู่ (เช่น คำขอลาที่ถูกยกเลิก) ซึ่งเป็นเรื่องปกติ ไม่ต้องอธิบายถ้าไม่ถูกถาม
- ถ้าหน้าจอไหนค้าง/แปลก ให้ refresh หนึ่งครั้งก่อน (Blazor ต่อ connection ใหม่ให้เอง) — อย่ากดซ้ำรัวๆ
- ห้ามพิมพ์รหัสผ่านให้ผู้ชมเห็นเป็นตัวอักษร — ใช้ช่องรหัสผ่านตามปกติ (จุดไข่ปลา) และอย่าเปิดเอกสารฉบับนี้ขึ้นจอฉาย

## 5. หลัง demo

- ข้อมูลที่สร้างระหว่าง demo (คำขอลา, ประเภทลาที่เพิ่มโชว์, enrollment) ค้างอยู่ในฐานทดสอบ — ถ้าจะ demo ซ้ำให้ลบ/ยกเลิกผ่านหน้าจอปกติ (อย่าลบตรงในฐานข้อมูล เพราะระบบเก็บ audit log ทุกการแก้ไข ซึ่งเป็นจุดขายอย่างหนึ่ง — โชว์ได้ด้วยซ้ำ)
- คำถามที่ตอบไม่ได้ในงาน ให้จดกลับมา แล้วเช็คกับ `docs/HRM_Feature_List.md` ก่อนตอบกลับลูกค้า — สถานะในไฟล์นั้นอ้างอิงจากโค้ดจริงเสมอ
