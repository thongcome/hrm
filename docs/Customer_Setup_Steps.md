# ขึ้นระบบให้ลูกค้าใหม่ — ทำตามทีละขั้น

> สำหรับ **ทีมติดตั้ง Advance Digital** · ปรับปรุง 22 ก.ย. 2569
> เอกสารนี้คือ "ทำอะไรบ้าง ตามลำดับ" ตั้งแต่เครื่องเปล่าจนลูกค้าใช้งานจริงได้
> สคริปต์ทั้งหมดอยู่ใน `tools/deploy/`

**หลักที่ห้ามลืม:** ฐานของลูกค้า **ไม่ได้มาจากฐานเดโม `hrm` (Advance Digital)** แต่มาจาก **แม่แบบสะอาด** ที่ไม่มีพนักงานสักคน แล้วเปลี่ยนชื่อบริษัทเป็นของลูกค้า — ไม่มีขั้นตอนไหนที่ต้อง "ลบข้อมูลเดโมทีหลัง" เพราะไม่เคยมีข้อมูลเดโมอยู่ในฐานลูกค้าตั้งแต่แรก

---

## ขั้นที่ 0 — เตรียมของก่อนไปหน้างาน

| ต้องมี | หมายเหตุ |
|---|---|
| SQL Server + สิทธิ์สร้างฐานข้อมูล | เครื่องลูกค้า หรือเครื่องเราตอนโชว์ |
| ไฟล์แม่แบบ `hrm_template_v*.bak` (รุ่นล่าสุด) | อยู่ในโฟลเดอร์ backup ของ SQL Server · สคริปต์หยิบไฟล์ใหม่สุดให้เอง · ถ้ายังไม่มี ดู "สร้างแม่แบบใหม่" ท้ายเอกสาร |
| โค้ด build แล้ว (`dotnet build -p:UseAppHost=false`) | `dotnet run --no-build` จะได้ไม่ต้องรอ compile หน้างาน |
| ข้อมูลลูกค้า | รหัสบริษัท (อังกฤษ ตัวพิมพ์ใหญ่ เช่น `ACME`), ชื่อไทย, ชื่ออังกฤษ, เลขประจำตัวผู้เสียภาษี 13 หลัก |
| ถ้าจะทำไฟล์โอนเงิน | **สเปกไฟล์ของธนาคารที่ลูกค้าใช้** หรือไฟล์ตัวอย่างที่ธนาคารให้มา (ถ้ายังไม่มี อย่ารับปากทำสดหน้างาน) |

## ขั้นที่ 1 — สร้างฐานของลูกค้า (คำสั่งเดียวจบ)

```powershell
cd D:\GitWorkspace\HRM
.\tools\deploy\new_customer.ps1 -Database hrm_acme -Code ACME `
    -Name "บริษัท เอซีเอ็มอี จำกัด" -NameEn "ACME Co., Ltd." -TaxId 0105561000001
```

สคริปต์ทำให้ 3 อย่าง:
1. **restore แม่แบบสะอาด** เป็นฐาน `hrm_acme` (แม่แบบมี: ระบบครบ, บริษัทเดียวเป็นโครงว่าง, `advadmin`, ค่าตั้งต้น — **ไม่มีพนักงาน ไม่มีรอบเงินเดือน ไม่มีข้อมูลเดโม**)
2. **เปลี่ยนบริษัทเป็นของลูกค้า** — ไล่เปลี่ยนรหัสบริษัทเป็น `ACME` ทุกคอลัมน์ที่เก็บเป็นสตริง (~117 คอลัมน์) พร้อมชื่อไทย/อังกฤษ/เลขผู้เสียภาษี — ไม่ต้องตั้งค่า "บริษัท active" แยกต่างหาก เพราะ HRM อ่านจาก `com_company.isActive` ในฐานข้อมูลตรงๆ (สคริปต์ตั้งให้แล้ว)
3. **ตั้งรหัสผ่าน `advadmin` ครั้งเดียว** — แสดงบนจอครั้งเดียว **จดไว้** ระบบบังคับเปลี่ยนตอน login แรก

> สคริปต์จะ **ปฏิเสธ** ถ้าฐานปลายทางมีอยู่แล้วและมีพนักงาน (กันทับฐานจริงของลูกค้ารายอื่น)

## ขั้นที่ 2 — เปิดระบบให้เข้าใช้ได้

```powershell
$env:ConnectionStrings__DefaultConnection = "Server=.;Database=hrm_acme;Integrated Security=true;TrustServerCertificate=true"
dotnet run --project .\HRM.csproj --no-build --urls http://0.0.0.0:5052
```

- ลูกค้าเปิดจากเครื่องตัวเองที่ `http://<ไอพีเครื่องที่รัน>:5052` (สคริปต์ขั้นที่ 1 พิมพ์ไอพีให้แล้ว)
- ใส่ `-Serve` ต่อท้ายคำสั่งขั้นที่ 1 ถ้าอยากให้รันต่อให้เลย
- **ตอนโชว์ลูกค้าให้ใช้ฐานของเขาเสมอ** ไม่ใช่ฐานเดโม ADVD — เขาจะเห็นชื่อบริษัทตัวเองตั้งแต่หน้า login
- Production จริง (IIS/บริการถาวร): ตั้ง `ASPNETCORE_ENVIRONMENT=Production` — OpenIddict จะสร้างใบรับรองของตัวเองอัตโนมัติที่ `App_Data/security/` (ดู `Program.cs`'s `LoadOrCreateOpenIddictCertificate`, ไม่ต้องเตรียมอะไรเพิ่ม)

login ด้วย `advadmin` + รหัสจากขั้นที่ 1 → ระบบบังคับตั้งรหัสใหม่ทันที

## ขั้นที่ 3 — ตั้งค่าบริษัท (ทำใน 4 หน้านี้ ตามลำดับ)

| # | หน้า | กรอกอะไร | ถ้าไม่ทำจะเป็นยังไง |
|---|---|---|---|
| 3.1 | `/pay/admin/payslip-settings` | ชื่อบริษัท (ไทย/อังกฤษ), **เลขประจำตัวผู้เสียภาษี**, ที่อยู่, **เลขที่บัญชีนายจ้างประกันสังคม + ลำดับสาขา**, **จังหวัดที่ตั้งสถานประกอบการ** | 50 ทวิ / ภ.ง.ด.1 / สปส.1-10 ออกมาไม่มีหัวเอกสาร **ยื่นไม่ได้** |
| 3.2 | `/pay/admin/bank-file-formats` | รูปแบบไฟล์โอนเงินตามสเปกธนาคารของลูกค้า | **ทำไฟล์โอนเงินไม่ได้** |
| 3.3 | `/pay/admin/minimum-wage` | ค่าจ้างขั้นต่ำรายวันตามประกาศจริงของจังหวัดนั้น + วันที่มีผล | ระบบไม่เตือนเมื่อจ่ายต่ำกว่าขั้นต่ำ |
| 3.4 | `/pay/admin/pay-schedules` | เฉพาะบริษัทที่จ่ายเดือนละ 2 งวด (ไม่ตั้ง = เดือนละงวด) | คำนวณสัดส่วนงวดผิด |

**ตรวจเพิ่มถ้าลูกค้ามีเรื่องเหล่านี้:** กองทุนสำรองเลี้ยงชีพ (`/pay/admin/provident-fund-policy`) · ประกันกลุ่ม (`/pay/admin/insurance-plans`) · นโยบายหักสาย-ขาดงาน (`/pay/admin/attendance-deduction`) · ประเภทรายการเงินได้-เงินหักเพิ่มเติม เช่น ค่าคอมมิชชั่น (`/pay/admin/pay-item-types`) · วันหยุดประจำปี (`/leave-requests/holidays`) · ถ้าลูกค้าย้ายพนักงานเข้ากลางปีจากนายจ้างเดิม — เงินได้สะสมที่นายจ้างเดิมหักภาษีไว้แล้ว (`/pay/admin/prior-employer-income`, จากหนังสือรับรองหัก ณ ที่จ่าย 50 ทวิ)

## ขั้นที่ 4 — ผู้ใช้และสิทธิ์

1. `/admin/system/users` สร้างผู้ใช้ของลูกค้า แล้วให้บทบาท:
   - **`PAYROLL_OFFICER` (เจ้าหน้าที่เงินเดือน)** — คำนวณ, ส่งอนุมัติ, บันทึกบัญชี, ไฟล์ธนาคาร, ยืนยันจ่าย
   - **`PAYROLL_APPROVER` (ผู้อนุมัติเงินเดือน)** — อนุมัติรอบในกล่องงาน
2. **ต้องเป็นคนละคน** — ระบบบังคับแยกหน้าที่ คนที่คำนวณ/ส่งอนุมัติรอบไหน จะอนุมัติรอบนั้นเองไม่ได้ แม้เป็น Admin
3. ถ้าใช้ workflow อนุมัติ (เปิดมาให้แล้ว): `/wf/sub-workflow-levels` ตรวจว่าขั้นอนุมัติมีผู้อนุมัติจริง
4. สิทธิ์การใช้งานแต่ละหน้า (สร้าง/แก้/ลบ) ตั้งแยกต่อบทบาทได้ที่ `/admin/system/program-rights` (AD.CRUDManage — ทุกบทบาทเริ่มต้นเป็น "อ่านอย่างเดียว" ยกเว้น Admin)
5. `advadmin` เป็นบัญชีของทีมติดตั้ง — **ห้ามลบ ห้ามปิด** ส่งมอบแล้วเปลี่ยนรหัสและเก็บไว้

## ขั้นที่ 5 — นำเข้าพนักงาน (เครื่องมือของทีมติดตั้ง)

> หน้านี้เปิดเฉพาะช่วงติดตั้ง — ควบคุมด้วย `"Deploy": { "InstallerTools": true }` ใน appsettings ของเครื่องนั้น

1. `/hr/employee-import` → **ดาวน์โหลดแบบฟอร์ม** (ไฟล์สร้างตามข้อมูลบริษัทนั้น มี dropdown ธนาคาร/คำนำหน้า/หน่วยงาน)
2. ให้ลูกค้ากรอก: **หน่วยงาน** → **พนักงาน**
3. อัปโหลด → ระบบตรวจทุกแถว **ยังไม่บันทึกอะไร** จนกว่าจะกดยืนยัน
4. ถ้ามีข้อผิดพลาด → ดาวน์โหลดไฟล์ที่ระบบ **ทำเครื่องหมายไว้ในช่องที่ผิด** ให้ลูกค้าแก้แล้วอัปใหม่
5. อัปซ้ำได้ — รหัสพนักงาน/หน่วยงานเดิมจะถูก**อัปเดต ไม่สร้างซ้ำ**

**ถ้าขึ้นระบบกลางปีและพนักงานย้ายมาจากนายจ้างเดิม:** กรอกเงินได้สะสม/ภาษีที่นายจ้างเดิมหักไว้ที่ `/pay/admin/prior-employer-income` (จากหนังสือรับรอง 50 ทวิ ของนายจ้างเดิม) ไม่งั้นภาษีหัก ณ ที่จ่ายรายเดือนจะต่ำกว่าที่ควร เพราะระบบนับเงินได้สะสมทั้งปีจากศูนย์

## ขั้นที่ 6 — ตรวจความพร้อมก่อนใช้งานจริง

```powershell
sqlcmd -S . -d hrm_acme -i .\tools\deploy\30_check_ready.sql -f 65001
```

`-f 65001` (UTF-8 codepage) **ต้องใส่เสมอ** — สคริปต์นี้ใช้ภาษาไทยเป็นชื่อคอลัมน์จริงในโค้ด ไม่ใช่แค่ในคอมเมนต์ ถ้าลืมจะได้ error "Incorrect syntax" แทนผลตรวจ

สคริปต์อ่านอย่างเดียว แล้วบอกเป็นรายการว่า **ผ่าน / ควรกรอก / ต้องแก้** — ครอบคลุม: บริษัท, ไม่มีข้อมูลเดโมหลงเหลือ, `advadmin`, ตั้งค่าสลิป, อัตราประกันสังคม, ตารางภาษีปีนี้, ไฟล์ธนาคาร, ค่าจ้างขั้นต่ำ, ผู้ทำ/ผู้อนุมัติเงินเดือน, workflow อนุมัติ, พนักงาน (รวมคนที่ไม่มีเลขบัญชี/ไม่มีเงินเดือน), วันหยุด, เงินได้จากนายจ้างเดิม (ถ้าขึ้นระบบกลางปี), สิทธิ์หน้าจอ (AD.CRUDManage)

**ต้องไม่เหลือ "ต้องแก้" ก่อนไปขั้นถัดไป**

## ขั้นที่ 7 — รอบเงินเดือนแรก (ทำคู่กับลูกค้า)

1. `/pay/runs` → สร้างรอบของงวดนั้น
2. **ตรวจสอบข้อมูลก่อนประมวลผล (Pre-flight)** — ถ้ายังมีข้อ "ผิดพลาด" ระบบไม่ยอมให้คำนวณหรือส่งอนุมัติ
   - ทางแก้มีสองทางเสมอ: แก้ข้อมูลของคนนั้น หรือ **พักการจ่าย (hold)** คนนั้นไว้รอบนี้
3. คีย์รายการรายงวด (ถ้ามี) — ค่าคอมมิชชั่น/เบี้ยเลี้ยง/เงินหัก คีย์ทีละหลายคนหรืออัปจาก Excel → **ต้องกดอนุมัติ** ก่อน ไม่งั้นไม่เข้ารอบ
4. **คำนวณ** → ตรวจผล → ดูผลตรวจความผิดปกติ (anomaly)
5. **ส่งอนุมัติ** → ผู้อนุมัติกดอนุมัติในกล่องงาน (`/wf/my-inbox`)
6. **บันทึกบัญชี (Post)** → **สร้างไฟล์ธนาคาร** → ส่งธนาคาร → **ยืนยันจ่ายแล้ว**
7. สลิป: สร้าง → เผยแพร่ให้พนักงานดูใน ESS

> **รอบที่จ่ายแล้วแก้ไม่ได้** — จ่ายผิดให้บันทึกเงินได้/เงินหักรายครั้งในงวดถัดไป (ไม่มีรอบกลับรายการโดยตั้งใจ)

## ขั้นที่ 8 — ส่งมอบ / ปิดงาน

1. **ปิดเครื่องมือช่วงติดตั้ง** — ใน appsettings ของเครื่องลูกค้า ตั้ง
   ```json
   "Deploy": { "InstallerTools": false }
   ```
   หน้านำเข้าพนักงานจะปิดทันที (ป้องกันพนักงานลูกค้าอัปไฟล์ทับทะเบียนพนักงานทั้งบริษัท)
2. **เปลี่ยนรหัส `advadmin`** และเก็บไว้ที่ทีมติดตั้ง (ห้ามลบบัญชี)
3. **ตั้ง backup ฐานข้อมูลอัตโนมัติ** ของลูกค้า
4. สอนผู้ใช้ 3 บทบาท: เจ้าหน้าที่เงินเดือน / ผู้อนุมัติ / พนักงาน (ESS ดูสลิป/ยื่นลา)
5. เก็บไฟล์ผลลัพธ์ `30_check_ready.sql` ล่าสุดไว้เป็นหลักฐานว่าส่งมอบตอนสถานะไหน

## สร้างแม่แบบใหม่ (ทำเมื่อมี migration ใหม่เท่านั้น)

ทำที่เครื่องเรา ไม่ใช่ที่ลูกค้า

1. ลง migration ใหม่ทั้งหมดบน `hrm` ของเรา
2. สำรอง `hrm` (`BACKUP DATABASE hrm ... WITH COPY_ONLY`) แล้ว restore เป็น `hrm_template`
3. รัน `10_make_clean_template.sql` กับ `hrm_template` (ลบพนักงาน/รอบ/งาน/ผู้ใช้ทั้งหมด เหลือระบบ + บริษัทเดียว + `advadmin`) — สคริปต์รันได้เฉพาะฐานที่ชื่อมีคำว่า `template`, และ**ไม่ได้ห่อทั้งหมดในธุรกรรมเดียว** (เจตนา — การล้างข้อมูลนับแสนแถวในธุรกรรมเดียวเคยทำให้ log ฐานข้อมูลทดสอบเต็มระหว่างสร้างสคริปต์นี้จริง) ปลอดภัยที่จะรันซ้ำถ้าล้มเหลวกลางทาง
4. `BACKUP DATABASE hrm_template TO DISK='...\hrm_template_v<N>.bak' WITH COPY_ONLY, CHECKSUM`
5. ทดสอบแม่แบบด้วยการติดตั้งลูกค้าทดสอบจริงหนึ่งราย (ขั้นที่ 1-6 ข้างบน) ก่อนเอาไปใช้กับลูกค้าจริง
6. ประกอบชุดติดตั้งใหม่ด้วย `.\tools\deploy\make_install_kit.ps1 -Version <N>` แล้วบันทึกรุ่นใหม่ในตารางของ `D:\GitWorkspace\Advance.Platform\HumanOk\README.md`
