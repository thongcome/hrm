# ติดตั้ง HumanOk ให้ลูกค้าใหม่ (ฐานข้อมูลสะอาด ไม่มีข้อมูลเดโม)

> 👉 **ทำตามทีละขั้นจนจบงาน (ตั้งค่า → นำเข้าพนักงาน → รอบแรก → ส่งมอบ): [docs/Customer_Setup_Steps.md](../../docs/Customer_Setup_Steps.md)**
> ไฟล์นี้อธิบายกลไกของสคริปต์แต่ละตัว · ขั้นที่ 1–2 ของคู่มือนั้นรวบเป็นคำสั่งเดียวแล้วที่ `new_customer.ps1`
> ตรวจความพร้อมก่อนใช้งานจริงด้วย `30_check_ready.sql`

> ระบบของลูกค้า **ไม่มีปุ่มล้างข้อมูล** — เริ่มจากฐานสะอาดเสมอ ข้อมูลเดโมมีเฉพาะฐานของเราเอง (`hrm`)
> ทุกคำสั่ง `sqlcmd` ที่รันสคริปต์เหล่านี้ **ต้องใส่ `-f 65001`** (UTF-8 codepage) — ไม่งั้นข้อความ/ชื่อ
> คอลัมน์ภาษาไทยจะถูกถอดรหัสผิด และ `30_check_ready.sql` (ที่ใช้ภาษาไทยเป็นชื่อคอลัมน์จริง) จะพังตั้งแต่ parse

## ภาพรวม

```
hrm (ฐานเดโมของเรา)
   │  backup → restore เป็น hrm_template
   ▼
10_make_clean_template.sql   → ฐานแม่แบบ: โครงระบบ + ค่าตั้งต้น + บริษัทเดียว (ADVD) + advadmin
   │  backup เป็น hrm_template_vX.bak   ← ไฟล์ที่ใช้ติดตั้งทุกลูกค้า
   ▼  restore เป็นชื่อฐานของลูกค้า
20_new_customer.sql          → เปลี่ยน ADVD เป็นรหัสบริษัทลูกค้า + ชื่อ + เลขผู้เสียภาษี
   ▼
HRM.dll --init-admin         → รหัสผ่านชั่วคราวของ advadmin (แสดงครั้งเดียว ต้องเปลี่ยนตอนเข้าครั้งแรก)
   ▼
ลูกค้า: ตั้งค่าบริษัท → ดาวน์โหลดแบบฟอร์ม → นำเข้าพนักงาน → ใช้งานจริง
```

`new_customer.ps1` ทำ 3 ขั้นแรกให้ในคำสั่งเดียว — ดูตัวอย่างใน [docs/Customer_Setup_Steps.md](../../docs/Customer_Setup_Steps.md) ขั้นที่ 1

## 1. สร้างฐานแม่แบบ (ทำครั้งเดียวต่อรุ่นที่ออก — ทีมเรา)

1. ลง migration ล่าสุดใน `hrm` ให้ครบก่อน (ดู CLAUDE.md หัวข้อ EF Core migrations)
2. `BACKUP DATABASE hrm ... WITH COPY_ONLY` แล้ว `RESTORE` เป็น **`hrm_template`**
3. รัน `10_make_clean_template.sql -f 65001` บน `hrm_template` — สคริปต์รันเฉพาะฐานที่ชื่อมีคำว่า `template`

   **ไม่ได้ห่อทั้งหมดในธุรกรรมเดียว โดยตั้งใจ** — HRM ล้างข้อมูลหลายแสนแถวใน ~150 ตาราง (`AuditLog` เพียง
   ตารางเดียวอาจมีหลักแสน) ตอนสร้างสคริปต์นี้จริงพบว่าธุรกรรมเดียวทำให้ transaction log ของฐานทดสอบเต็ม
   กลางทาง (error 3930) — ขั้นที่ 1 (ล้างข้อมูล) จึง commit ทีละตารางและปลอดภัยที่จะรันซ้ำถ้าหยุดกลางทาง
   ส่วนขั้นที่ 2 (กรองข้อมูลบริษัทที่เก็บ) มีขนาดเล็กพอที่จะอยู่ในธุรกรรมเดียวและย้อนกลับได้ถ้าผิดพลาด
   ผลที่ต้องเห็นตอนจบ: ตาราง `employees 0 · users 1 · companies 1 · orgs 1 · runs 0 · jobs 0 ·
   audit_rows 0` และข้อความ `TEMPLATE READY`

4. `BACKUP DATABASE hrm_template TO DISK='...\hrm_template_vX.bak' WITH COPY_ONLY, CHECKSUM`

**ฐานแม่แบบเก็บอะไร:** เมนู/บทบาท/สิทธิ์รายหน้า (AD.CRUDManage), workflow + ขั้นอนุมัติ + ผู้อนุมัติตามบทบาท,
ธนาคาร 17 แห่ง, ตารางภาษี, ประเภทค่าลดหย่อน, ประเภทเงินได้-เงินหัก, ประเภทการลา, ตำแหน่ง/ระดับ, ภาษา ·
ค่าตั้งต้นของบริษัท (อัตราประกันสังคม, นโยบายการลา+วันหยุด, นโยบายหักสาย/ขาด, ตั้งค่าสลิป — **ล้างรหัสผ่าน
ตั้งต้นทิ้ง**, บัญชี GL, ประเภทพนักงาน, แคตตาล็อกสวัสดิการ) · บริษัทเดียว + หน่วยงานระดับบริษัท 1 แถว
(ล้าง `boss_hremployee_id`/`approver_hremployee_id`/`parentID` ทุกตัว — ไม่มีอะไรผูกกับพนักงานเดโม) ·
บัญชี `advadmin` (**ต้องมีเสมอ — เป็นบัญชีติดตั้ง**, ไม่ผูกพนักงาน, ไม่มีรหัสผ่านติดไป)

**ล้างทิ้ง:** พนักงาน, ผังองค์กรเดโม, อัตรากำลัง, ผู้ใช้เดโม, รอบเงินเดือน, ใบลา/OT/เบิก, งาน workflow,
AuditLog, บริษัทอื่น, แคตตาล็อก/เนื้อหาของทุกโมดูล (ประเมินผล, IDP, สรรหา, LMS, KM, OKR, Engagement,
กองทุนสำรองเลี้ยงชีพ/ประกันกลุ่ม/ค่าคอมมิชชั่นของบริษัทเดโม ฯลฯ), ผู้อนุมัติที่ผูกกับคนเดโม (`wf_custom_user`,
`wf_adhoc_user`, `wf_loa`, `wf_employee`) — **ลูกค้าต้องตั้งผู้อนุมัติ workflow ใหม่** (workflow ที่ผู้อนุมัติ
เป็นบทบาท เช่น อนุมัติรอบเงินเดือน ใช้ได้ทันทีเมื่อกำหนดบทบาทให้คน, ไม่ต้องตั้งอะไรเพิ่ม)

## 2. ติดตั้งลูกค้าใหม่

1. `RESTORE DATABASE <ชื่อฐานลูกค้า> FROM DISK='...\hrm_template_vX.bak' WITH MOVE ...`
2. ตั้งค่าตัวแปรผ่านไฟล์ ไม่ใช่ `sqlcmd -v` บน command line ตรงๆ (ชื่อบริษัทภาษาไทยจะถูกทำลายด้วยการเข้ารหัส
   ของ Windows console ก่อนถึง sqlcmd — ตรวจพบจริงตอนสร้างสคริปต์นี้):
   ```
   :setvar CODE "NEWCO"
   :setvar NAME "บริษัท นิวโค จำกัด"
   :setvar NAME_EN "NewCo Co., Ltd."
   :setvar TAXID "0105560000000"
   :r 20_new_customer.sql
   ```
   ```
   sqlcmd -S <server> -d <ชื่อฐานลูกค้า> -i install_vars.sql -f 65001
   ```
   - ปฏิเสธถ้าเป็นฐานของเราเอง, ถ้าไม่ใช่แม่แบบที่ยังไม่ถูกแตะ (ต้องมีบริษัทเดียวรหัส ADVD และไม่มีพนักงาน),
     รหัสยาวเกินคอลัมน์ที่แคบที่สุด (ตรวจ ~117 คอลัมน์สตริงที่เก็บรหัสบริษัท)
   - เปลี่ยน ADVD → รหัสลูกค้าในทุกคอลัมน์รหัสบริษัท **สตริง** เท่านั้น — คอลัมน์ตัวเลข (`sc_user.company_id`,
     `sc_role.company_id`, `com_organization.companyid`) ไม่ต้องแตะ เพราะยังชี้ไปที่แถว `com_company` เดิม
     ไม่ว่ารหัสของแถวนั้นจะถูกเปลี่ยนเป็นอะไร (ดู CLAUDE.md "Company scoping is a string, not a numeric FK")
3. `dotnet HRM.dll --init-admin` (หรือ `dotnet run --no-build -- --init-admin`) → จดรหัสผ่านชั่วคราวของ
   `advadmin` ที่แสดงครั้งเดียว ส่งให้ผู้ดูแลลูกค้าทางช่องทางปลอดภัย — HRM ไม่มี appsettings "บริษัท active"
   แยกต่างหากให้ตั้ง (ต่างจาก Advance.Payroll) เพราะ `ActiveCompanyHelper` อ่าน `com_company.isActive` จาก
   ฐานข้อมูลตรงๆ และแม่แบบมีบริษัทเดียวอยู่แล้ว
4. เปิดระบบ → เข้าด้วย `advadmin` → ระบบบังคับเปลี่ยนรหัสผ่าน
5. เครื่องจริงตั้ง `ASPNETCORE_ENVIRONMENT=Production` เสมอ — ข้อมูลเดโมไม่มีทางถูกสร้าง (`DevAuthSeeder`
   ใช้ได้เฉพาะ `IsDevelopment()`) และ OpenIddict จะสร้าง/เก็บใบรับรองของตัวเองอัตโนมัติที่
   `App_Data/security/` แทนใบรับรอง dev-only

`new_customer.ps1` ทำขั้น 1–3 ให้อัตโนมัติ (ไม่ต้องแก้ปัญหาการเข้ารหัส Thai เอง — สคริปต์อ่านค่าจาก parameter
ของ PowerShell โดยตรง ไม่ผ่าน `sqlcmd -v`)

## 3. ตรวจความพร้อม

```
sqlcmd -S <server> -d <ชื่อฐานลูกค้า> -i 30_check_ready.sql -f 65001
```

อ่านอย่างเดียว ไม่แก้อะไร — รายละเอียดรายการตรวจอยู่ใน [docs/Customer_Setup_Steps.md](../../docs/Customer_Setup_Steps.md) ขั้นที่ 6

## 4. ประกอบชุดติดตั้ง

```powershell
.\make_install_kit.ps1 -Version 1.0 -Note "ชุดติดตั้งแรก"
```

ประกอบทุกอย่างข้างบน (แม่แบบล่าสุด + สคริปต์ + `dotnet publish` + คู่มือ) เป็นโฟลเดอร์เดียวที่
`D:\GitWorkspace\Advance.Platform\HumanOk\v<รุ่น>-<วันที่>\` พร้อมก๊อปลง USB ไปหน้างาน — ดูรายละเอียดใน
comment header ของไฟล์
